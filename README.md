# HD-2D 騎馬戰場原型

原創 HD-2D 中世紀騎馬軍團戰鬥的**技術原型**（Godot 4 + GDScript）。
目前完成研究報告規劃的**階段 0～3**：場景與相機、玩家與馬、集中式戰場管理器、50／100／200 人壓力測試。

> 全部使用程式產生的佔位圖形（色塊人形、簡單馬形），不含任何既有遊戲的名稱、角色或素材。
> 相機、美術路線、方向數、程式語言都還是**暫定方向**，架構刻意保留切換空間。

---

## 1. 在自己電腦上開啟

1. 安裝 **Godot 4.5 以上的標準版**（不需要 .NET 版）：<https://godotengine.org/download>
2. 下載這個程式庫（`git clone`，或在 GitHub 按 **Code → Download ZIP** 後解壓縮）。
3. 開啟 Godot → 專案管理員按 **匯入（Import）** → 選擇資料夾裡的 `project.godot` → **匯入並編輯**。
   第一次開啟會花幾秒建立快取，屬正常現象。
4. 按 **F5**（或右上角 ▶）執行主場景 `scenes/battlefield.tscn`。

> 如果 Godot 版本是 4.4，打開時會詢問是否轉換專案，選「是」通常即可；建議直接用 4.5 以上。

## 2. 操作

| 按鍵 | 功能 |
|---|---|
| WASD | 移動（以相機方向為準） |
| Shift | 步行時奔跑／騎馬時奔馳 |
| E | 靠近馬時上馬；騎馬時下馬 |
| 左鍵 或 空白鍵 | 揮擊（步行、騎馬都可以） |
| 滑鼠移動／滾輪 | 旋轉相機／拉近拉遠 |
| 1 / 2 / 3 | 全軍衝鋒 ／ 在此集結（守位）／ 跟隨我 |
| R | 重開戰局（固定亂數種子，每次開局相同） |
| F2 | 切換方向數：8 方向 → 5 方向＋鏡像 → 4 方向 |
| F3 | 除錯繪製：刀身掃掠軌跡、馬的前進方向、小隊集結點、士兵目標線 |
| F4 | 切換士兵畫面後端：Sprite3D ↔ MultiMesh |
| F5 | 後製效果（景深、泛光、SSAO、霧）開關 |
| F6 | Billboard 方式：Y 軸直立 ↔ 完全面向相機 |
| Esc | 釋放滑鼠（點畫面重新鎖定） |

開局時玩家站在我軍後方，馬在右手邊。我軍預設守位；敵軍約 10 秒後（或我軍逼近時）全軍衝鋒。

## 3. 各階段要試玩確認的地方

研究報告建議每個階段結束都由你實際玩一次，對照下面的驗收重點：

**階段 0：場景與相機**
- 角色站在斜坡上（戰場東側有一道明顯斜坡）時，腳有沒有貼地、會不會漂浮。
- 旋轉相機時，角色的方向圖切換是否正確、會不會閃動（F2 可比較 8／5＋鏡像／4 方向）。
- 像素是否清晰。F6 可比較兩種 Billboard：Y 軸直立在畫面邊緣會有透視傾斜，面向相機則永遠直立。

**階段 1：玩家與馬**
- 奔馳、急停、轉彎時，騎士層與馬層有沒有錯位（F3 可看馬的前進方向）。
- 上下馬會不會卡進岩石（下馬會依序嘗試馬的左、右、後、前方，挑第一個空位）。
- 「騎馬好不好玩」：加速、轉向半徑、急轉減速等數值都在 `scripts/actors/horse.gd` 最上方，可在檢查器直接調。

**階段 2：戰場管理器與士兵**
- 士兵依小隊走位不重疊、不卡住；騎馬衝進人群時馬會減速，前方士兵會往旁邊閃。
- 騎馬中按 1／2／3 下令，命令在下一個物理步就被小隊取用並開始執行，正在交戰的士兵不會瞬間失去目標。
- 不操作玩家時，戰鬥能自己打完（雲端以 50 對 50 實測約 60 秒分出勝負）。
- 揮擊命中：迎面衝鋒的傷害應明顯高於同向追擊；同一次揮擊不會重複命中同一人（F3 看掃掠軌跡）。

### 揮擊手感（純畫面／聲音回饋，`scripts/fx/combat_fx.gd`）
- **刀光拖尾**沿揮擊弧線淡出；揮擊速度前後慢、中段快。
- **左右連段**：每刀交替右→左、左→右；收招中再按攻擊會**緩衝**，收招一結束就接下一刀。
- **命中停頓**（約 0.05 秒，擊殺約 0.1 秒，衝鋒越快停越久）、**鏡頭微震**、**火花**、**傷害數字**。
- **擊退**改成滑出去（含致命一擊的屍體），衝鋒速度越快退越遠。
- **佔位音效**全部由程式合成（不用外部音檔）：揮砍「咻」、砍中「嚓咚」、擊殺較重的一聲、騎馬衝撞「砰」、周圍士兵刀槍相擊「鏘」（有距離衰減，每秒最多約 10 聲）。
- **騎馬衝撞**：奔馳超過 5 m/s 正面撞上敵兵會造成傷害並把人撞飛，速度越快越痛（這一項是玩法，數值在 BattleManager 的 trample_*）。
- 這些回饋都不影響判定：拿掉 CombatFX，戰鬥結果完全一樣。數值都在 CombatFX 最上方，可在檢查器調整。

## 4. 壓力測試（階段 3，決策點）

### 在編輯器裡執行（最簡單）
1. 在檔案系統面板打開 `scenes/stress_test.tscn`。
2. 按 **F6**（執行目前場景）。
3. 會自動依序測：**Sprite3D 50／100／200 人 → MultiMesh 50／100／200 人**，每次暖機 3 秒＋記錄 20 秒，總共約 2.5 分鐘。期間相機會自動繞場，不用操作。
4. 測完畫面會顯示摘要表，**摘要同時已複製到剪貼簿**，直接貼回對話給我即可。按 Esc 結束。

### 用命令列執行（可自訂參數）
```bash
# Windows 範例（路徑換成你的 Godot 執行檔）
"C:\Godot\Godot_v4.5.1-stable_win64.exe" --path . res://scenes/stress_test.tscn -- --counts=50,100,200,400 --quit

# macOS 範例
/Applications/Godot.app/Contents/MacOS/Godot --path . res://scenes/stress_test.tscn -- --counts=50,100,200
```
`--` 之後的參數：

| 參數 | 說明 |
|---|---|
| `--counts=50,100,200` | 士兵總數（雙方合計），可加 400、800 找上限 |
| `--backends=sprite,multimesh` | 要測的士兵畫面後端 |
| `--duration=20` `--warmup=3` | 每次記錄秒數與暖機秒數 |
| `--immortal` | 士兵不死亡，整段維持固定人數 |
| `--no-postfx` | 關閉景深／泛光／SSAO／霧，比較後製成本 |
| `--quit` | 測完自動關閉 |

### 結果檔案位置
- Windows：`%APPDATA%\Godot\app_userdata\HD-2D Battle Prototype\stress_results\`
- macOS：`~/Library/Application Support/Godot/app_userdata/HD-2D Battle Prototype/stress_results/`
- Linux：`~/.local/share/godot/app_userdata/HD-2D Battle Prototype/stress_results/`

每次測試會產生：`stress_時間.txt`（摘要表，含 CPU／GPU 型號）、`stress_時間_summary.csv`、每一輪的逐幀 CSV。

### 摘要表欄位
| 欄位 | 意義 |
|---|---|
| 平均 FPS／1% 低 FPS | 1% 低 = 最慢 1% 幀的平均，代表卡頓感 |
| 平均幀 ms／P99／最差幀 ms | 幀時間分布 |
| 邏輯平均／最差 ms（網格／決策／移動） | 戰場管理器每個物理步（60Hz）的耗時與分解 |
| 畫面更新 ms | 視覺代理把士兵資料寫進 Sprite3D／MultiMesh 的耗時 |
| CPU 繪製 ms／GPU ms | 引擎渲染耗時（GPU 量測依驅動支援） |
| DrawCalls | 每幀繪製呼叫數，MultiMesh 應明顯較少 |
| 結束存活 | 測試結束時雙方存活人數 |

**目前不設幀率門檻**，看完數據再決定：繼續 → 階段 4，或先把熱點改寫（C#／GDExtension）、改用 MultiMesh、降低同場人數加增援波次。

### 雲端參考數據（只有邏輯，沒有繪圖）
雲端環境沒有顯示卡，以下只代表「戰場邏輯」在 4 執行緒 2.1GHz Xeon 上的耗時，**畫面相關數字要以你電腦的結果為準**：

| 士兵數 | 邏輯平均 ms／物理步 | 最差 ms | 其中「移動與戰鬥」 |
|---|---|---|---|
| 50 | 0.45 | 1.5 | 0.34 |
| 100 | 0.87 | 2.1～6.4 | 0.69 |
| 200 | 2.1 | 4.7～7.6 | 1.7 |
| 400 | 5.1 | 11.6～12.2 | 4.3 |

以 60Hz 物理步、一幀 16.7 ms 來看，200 人時邏輯約占 13%；400 人時約占 30%，熱點在「移動與戰鬥」（分離力的鄰居迴圈），是之後改 C#／GDExtension 或降頻的首選目標。

## 5. 架構概覽

```
scripts/
  core/game_config.gd          全域暫定選項（方向數、士兵畫面後端、Billboard、後製、亂數種子）與輸入對應
  world/battle_terrain.gd      高度圖地形：網格＋HeightMapShape3D（給玩家/馬）＋ get_height()（給士兵）
  camera/orbit_follow_camera.gd 可旋轉第三人稱追隨相機（移軸景深）
  actors/horse.gd              馬：CharacterBody3D＋自訂加速、轉向率、慣性
  actors/player.gd             玩家：步行/騎乘、上下馬、掃掠揮擊、傷害公式
  battle/battle_manager.gd     集中式戰場管理器：士兵資料陣列、空間網格、三層 AI、戰鬥、命令佇列
  battle/soldier_renderer.gd   士兵視覺代理介面（共用：方向、動作幀、陰影）
  battle/sprite_soldier_renderer.gd     實作 A：每人一個 Sprite3D
  battle/multimesh_soldier_renderer.gd  實作 B：全體一個 MultiMesh（shaders/soldier_billboard.gdshader）
  visual/direction_util.gd     朝向 → 方向圖欄位（8 欄規格；4 方向、5＋鏡像由設定決定）
  visual/anchor_set.gd         錨點資料（之後可由 Aseprite 匯出的 JSON 轉入）
  visual/layered_actor_visual.gd 主圖層＋附掛圖層（馬＋騎士）＋陰影的視覺代理
  visual/placeholder_art.gd    程式產生的佔位像素圖與錨點
  debug/stress_test.gd         壓力測試
  debug/scenario_runner.gd     開發用自動腳本（模擬按鍵＋截圖）
```

設計原則（依研究報告）：
- **戰鬥邏輯與畫面分離**：位置、命中都在 3D 空間用數學計算；Sprite 只負責「看起來像」。士兵畫面換成 MultiMesh 或預渲染 3D，戰鬥程式不用改。
- **士兵不進物理引擎**：只有玩家和馬是 CharacterBody3D。士兵靠高度圖貼地、靠空間網格互相分離與找敵。
- **方向數是設定值**：素材一律按 8 欄排；4 方向或 5＋鏡像只是換算方式不同。
- **分層＋錨點**：騎士的座位錨點對齊馬當前幀的鞍座錨點，奔馳起伏時騎士會跟著動；面向鏡頭時馬頭畫在騎士前面。
- **固定步長與固定種子**：戰鬥在 60Hz 物理步結算；同一種子重跑結果一致（雲端實測兩次 50 對 50 結果相同）。
- **命令只寫入佇列**：玩家下令不直接改士兵狀態，由小隊層下一次決策時取用。

## 6. 已知限制與下一步

- 士兵沒有士氣／撤退、沒有尋路（開闊地直走＋分離力；岩石用圓形障礙推開）。
- 個人 AI 的「遠處每 2～4 幀移動一次並內插」尚未實作，目前所有士兵每個物理步都移動；這是壓力測試後最直接的優化點。
- 玩家揮擊只有一種橫掃；左右揮、前刺、長槍衝鋒、命中停頓／音效／粒子屬於階段 5。
- 敵方指揮官只是「10 秒後或被逼近時全軍衝鋒」的佔位 AI；完整命令與分層 AI 屬於階段 6。
- 相機不會自動轉到馬的背後，需要用滑鼠轉；騎馬手感與相機行為等你試玩後再調。

## 7. 開發用工具

```bash
# 自動騎馬並截圖（--shots 指定輸出資料夾）
godot --path . -- --scenario=ride --shots=/tmp/shots --debug-draw
# 錄製展示影片（Godot Movie Maker，逐幀輸出，不受電腦速度影響）
godot --path . --write-movie demo.avi --fixed-fps 30 -- --scenario=demo --debug-draw
# 玩家不操作，每 10 秒印出戰況，直到分出勝負
godot --headless --path . --fixed-fps 60 -- --scenario=battle
```
