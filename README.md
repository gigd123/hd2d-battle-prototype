# HD-2D 騎馬戰場原型

原創 HD-2D 中世紀騎馬軍團戰鬥的**技術原型**（Godot 4 + GDScript）。
目前完成研究報告規劃的**階段 0～3**：場景與相機、玩家與馬、集中式戰場管理器、50／100／200 人壓力測試。

> 角色預設使用「3D 預渲染像素圖」：由程式生成的原創低模騎士與馬，經 `tools/sprite_baker` 自動烘焙成 8 方向分層像素圖（見 [docs/美術流程_3D預渲染.md](docs/美術流程_3D預渲染.md)）。按 F7 可切回舊的程式佔位圖。全部原創，不含任何既有遊戲的名稱、角色或素材。
> 相機、美術路線、方向數、程式語言都還是**暫定方向**，架構刻意保留切換空間。

## 1. 在自己電腦上開啟

1. 安裝 **Godot 4.5 以上的標準版**（不需要 .NET 版）：<https://godotengine.org/download>
2. 下載這個程式庫（`git clone`，或在 GitHub 按 **Code → Download ZIP** 後解壓縮）。
3. 開啟 Godot → 專案管理員按 **匯入（Import）** → 選擇資料夾裡的 `project.godot` → **匯入並編輯**。
   第一次開啟會花幾秒建立快取，屬正常現象。
4. 按 **F5**（或右上角 ▶）執行主場景 `scenes/battlefield.tscn`。

> 如果 Godot 版本是 4.4，打開時會詢問是否轉換專案，選「是」通常即可；建議直接用 4.5 以上。

## 2. 操作

| 按鍵 | 功能 |
|---|---|
| WASD | 移動（以相機方向為準）。步行時角色永遠面向滑鼠（相機）方向，WASD 不改朝向，可以邊打邊後退；後退 ×0.6、平移 ×0.8，只有往前能奔跑。騎馬也一樣由滑鼠決定方向：馬頭以有限的轉向速度轉向滑鼠方向，W 前進、S 慢慢倒退；A/D 在低速時是慢慢側步，前進中則讓馬頭往那邊偏 35° 走斜線 |
| Shift | 步行時奔跑／騎馬時奔馳 |
| E | 靠近馬時上馬；騎馬時下馬 |
| 左鍵 或 空白鍵 | 攻擊（步行、騎馬都可以；劍是橫掃、長槍是前刺） |
| 右鍵 或 C（按住） | 帶盾的武器：舉盾（正前方 75° 內減傷 85%，近戰和箭都擋）。雙手武器：用武器格擋（只擋近戰）。移動變慢、不能奔跑；蓄力中舉起會取消這一刀 |
| Q ／ Z | 換下一把／上一把武器（共 12 把，見下方武器表） |
| 弓：左鍵 | 按住拉弓、放開射出；拉得越滿箭越快、傷害越高，太早放開等於取消。拉弓時進入瞄準視角並出現準心 |
| 近戰：按住左鍵 | 停在揮擊前的預備姿勢，放開才揮出（傷害不會因為按得久而變高；`player.gd` 的 `hold_to_swing` 可關掉） |
| F | 弓的瞄準視角：第三人稱肩後 ⇄ 第一人稱 |
| 滑鼠移動／滾輪 | 旋轉相機（水平 360° 不限；上下從抬頭看天空 -60° 到幾乎正上方 88°。往下壓到地面時鏡頭停在低處改成抬頭，不會鑽地；俯角超過 72° 時角色自動改成完全面向相機）／拉近拉遠 |
| 1 / 2 / 3 | 全軍衝鋒 ／ 在此集結（守位）／ 跟隨我 |
| R | 重開戰局（固定亂數種子，每次開局相同） |
| F8 / F9 | 換下一種場地 ／ 隨機換場地（重新載入戰場） |
| F10 ／ F11 | 野戰 ⇄ 攻城戰（先選攻方或守方）／攻城戰中換邊並重開 |
| V | 觀戰鏡頭：拉遠到 46 公尺、俯角 22 度，繞著戰場中心慢慢轉（展示影片的角度）；滾輪調整距離，再按 V 回到玩家相機 |
| F2 | 切換方向數：8 方向 → 5 方向＋鏡像 → 4 方向 |
| F3 | 除錯繪製：刀身掃掠軌跡、馬的前進方向、小隊集結點、士兵目標線 |
| F4 | 切換士兵畫面後端：Sprite3D ↔ MultiMesh |
| F5 | 後製效果（景深、泛光、SSAO、霧）開關 |
| F6 | Billboard 方式：Y 軸直立 ↔ 完全面向相機 |
| F7 | 角色美術：預渲染 3D 像素圖 ↔ 程式佔位圖 |
| Esc | 釋放滑鼠（點畫面重新鎖定） |

開局時玩家站在我軍後方，馬在右手邊。我軍預設守位；敵軍約 10 秒後（或我軍逼近時）全軍衝鋒。

## 3. 各階段要試玩確認的地方

研究報告建議每個階段結束都由你實際玩一次，對照下面的驗收重點：

**階段 0：場景與相機**
- 角色站在斜坡上（戰場東側有一道明顯斜坡）時，腳有沒有貼地、會不會漂浮。
- 旋轉相機時，角色的方向圖切換是否正確、會不會閃動（F2 可比較 8／5＋鏡像／4 方向）。
- 像素是否清晰。F6 可比較兩種 Billboard：Y 軸直立在畫面邊緣會有透視傾斜，面向相機則永遠直立。

**階段 1：玩家與馬**
- 奔馳、急停、轉彎時，騎士層與馬層有沒有錯位（F3 可看馬的前進方向）。
- 上下馬會不會卡進岩石（下馬會依序嘗試馬的左、右、後、前方，挑第一個空位）。
- 「騎馬好不好玩」：加速、轉向半徑、急轉減速等數值都在 `scripts/actors/horse.gd` 最上方，可在檢查器直接調。

**階段 2：戰場管理器與士兵**
- 士兵依小隊走位不重疊、不卡住；騎馬衝進人群時馬會減速，前方士兵會往旁邊閃。
- 騎馬中按 1／2／3 下令，命令在下一個物理步就被小隊取用並開始執行，正在交戰的士兵不會瞬間失去目標。
- 不操作玩家時，戰鬥能自己打完（雲端以 50 對 50 實測約 60 秒分出勝負）。
- 揮擊命中：迎面衝鋒的傷害應明顯高於同向追擊；同一次揮擊不會重複命中同一人（F3 看掃掠軌跡）。

### 三兵種（步兵、弓兵、騎兵）
每方預設約 60% 步兵、25% 弓兵、15% 騎兵（以 10 人小隊為單位）。步兵在前排、弓兵在步兵後方、騎兵在兩翼。

| 兵種 | 生命 | 速度（走/跑 m/s） | 行為 |
|---|---|---|---|
| 步兵 | 100 | 3.0 / 4.2 | 長槍＋盾，近戰 |
| 弓兵 | 70 | 3.0 / 4.0 | 42 公尺內站定放箭（拋物線、會預判目標移動、距離越遠越散）；6 公尺內改用近戰，傷害低 |
| 騎兵 | 150 | 5.0 / 9.5 | 高速衝鋒，超過 6 m/s 撞上敵兵會造成傷害並撞飛；纏鬥 4 秒後脫離跑開再衝 |

- 箭矢是戰場管理器裡的資料（固定容量 384 支），只在接近地面高度時才檢查命中；敵方弓兵也會射玩家。
- 陣營色改成「調色盤交換」：貼圖裡純白的衣服才換成陣營色，馬和皮膚保持原色。
- 數值都在 `battle_manager.gd` 最上方的兵種數值表（`U_*`、`ARCHER_*`、`CAV_*`），編成比例是 `archer_ratio`、`cavalry_ratio`。

### 揮擊手感（純畫面／聲音回饋，`scripts/fx/combat_fx.gd`）
- **刀光拖尾**沿揮擊弧線淡出；揮擊速度前後慢、中段快。
- **左右連段**：每刀交替右→左、左→右；收招中再按攻擊會**緩衝**，收招一結束就接下一刀。
- **命中停頓**（約 0.05 秒，擊殺約 0.1 秒，衝鋒越快停越久）、**鏡頭微震**、**火花**、**傷害數字**。
- **擊退**改成滑出去（含致命一擊的屍體），衝鋒速度越快退越遠。
- **佔位音效**全部由程式合成（不用外部音檔）：揮砍「咻」、砍中「嚓咚」、擊殺較重的一聲、騎馬衝撞「砰」、周圍士兵刀槍相擊「鏘」（有距離衰減，每秒最多約 10 聲）。
- **騎馬衝撞**：奔馳超過 5 m/s 正面撞上敵兵會造成傷害並把人撞飛，速度越快越痛（這一項是玩法，數值在 BattleManager 的 trample_*）。
- 這些回饋都不影響判定：拿掉 CombatFX，戰鬥結果完全一樣。數值都在 CombatFX 最上方，可在檢查器調整。

### 試玩回饋修正（第二輪）
- **玩家受擊反應**：閃紅、0.32 秒硬直（移動變慢、蓄力會被打斷）、往攻擊來源反方向擊退、短暫停頓、鏡頭震動、受傷音效、畫面邊緣泛紅、紅色傷害數字。數值在 `player.gd` 的 `hurt_*`。
- **行軍不再卡卡**：正前方有友軍時放慢排隊、推擠速度平滑並設上限、轉身限速、走／停動畫加遲滯，人群裡不會來回抖動或每幀換方向圖。
- **俯視不再扁**：Y 軸 Billboard 依相機俯角把角色、樹往上拉長（腳底不動），強度是 `GameConfig.pitch_compensation`（0 關、1 完全補償，預設 0.85）。俯角很大時畫面邊緣的角色仍會有透視傾斜，F6 切成「完全面向相機」可以消除。
- **遮擋淡化**：玩家被樹或岩石擋住時，擋住的部分會以點陣挖空變成半透明（不用透明排序，效能穩定）。
- **馬腳不再陷進地面**：馬的畫面高度改用地形高度（前後蹄取平均），斜坡、雪地都會貼地。

### 試玩回饋修正（第三輪）
- **更快、步伐更大**：步行 4.4／奔跑 7.6 m/s，馬小跑 7.5／奔馳 15 m/s；走路、跑步、馬腿的擺幅都加大，動畫循環對應的步距也拉長，腳步不會滑。
- **邊走邊打有走路動作**：新增「邊走邊揮砍／邊走邊刺」的預渲染動畫（下半身照走、上半身出手）；騎馬攻擊時馬照跑。士兵也一樣：移動中出手用邊走邊攻擊的圖，騎兵原地出手時馬站著、移動中出手時馬繼續跑。
- **右鍵舉盾**：見操作表。擋下時有金屬聲、火花和「擋」字。
- **被打中會中斷動作**：蓄力、揮出、收招中被打中都會直接中斷（舉盾擋下的不算）。
- **劍與長槍**：長槍攻擊距離 2.7 m（騎馬 3.3 m），劍 1.6 m（騎馬 2.0 m）。長槍目標貼得比 1.1 m 還近時會「卡住」：傷害只剩 35%、這一刺直接結束並多 0.3 秒收招，畫面出現「卡住」。劍沒有這個限制。騎馬持長槍的衝鋒速度加成較高。士兵步兵也改拿長槍：攻擊距離 2.1 m，敵人貼太近會往後退一點拉開距離，貼身攻擊傷害減半。數值在 `player.gd` 的 `spear_*`、`block_*` 與 `battle_manager.gd` 的 `U_REACH`、`SPEAR_MIN_DIST`。

### 第五輪：蓄力與弓箭命中回饋
- 按住攻擊鍵時，蓄力動作做完會停在預備姿勢，放開才揮出；按一下就放開跟以前一樣直接揮出。傷害不變。
- 弓箭命中：準心外圍閃一個 ✕（擊殺是紅色、比較大），下方顯示「命中 32」或「擊殺！ 45」，加一個遠處也聽得到的「叮」，命中點火花加大。放箭後瞄準視角多停 0.7 秒，看得到箭飛出去有沒有中。
- 玩家移動加快約 12%：步行 5.0／奔跑 8.5 m/s，馬小跑 8.4／奔馳 16.8 m/s、倒退 2.9 m/s。動畫照走過的距離播放，腳步不會滑。

### 場地類型與高低起伏（`scripts/world/battle_terrain.gd`）
五種場地，F8 依序切換、F9 隨機；也可用啟動參數 `--terrain=plains|hills|forest|river|snow|random`。預設是丘陵。

| 場地 | 特色 |
|---|---|
| 平原 | 平坦開闊，起伏很小，騎兵最好發揮 |
| 丘陵 | 敵軍佔據東側山脊（高約 9 公尺），我軍要仰攻；另有我方後方小丘與北側高地 |
| 森林 | 交戰區內有成片樹叢（約 170 棵），會擋住士兵、玩家與馬，陣形會被打散 |
| 河谷 | 兩岸往中央下降，中間一條蜿蜒的河；深水處速度剩約 4 成，南北各一處淺灘幾乎不減速 |
| 雪地 | 稜線狀起伏較大，積雪讓所有人速度 ×0.88，霧較濃 |

- **坡度規則**（士兵、馬、步行玩家共用 `move_factor()`）：上坡依坡度減速（最低剩 35%），下坡稍快（最多 +14%）；涉水、積雪再乘上地面倍率。數值是 `uphill_penalty`、`downhill_bonus`。
- **弓兵高地優勢**：射手每比目標高 1 公尺，射程 +1.5 公尺（最多 +12）、箭傷 +4%（最多 +35%）；從低處往高處射則射程與傷害下降。數值在 `battle_manager.gd` 的 `HIGH_GROUND_*`。
- 障礙物（岩石、林中樹）改用 8 公尺格子索引，士兵只檢查附近的障礙，森林場地的邏輯成本仍很低。
- 雲端 50 對 50 不操作玩家的結果（同一個亂數種子；我軍守位、敵軍衝鋒）：
  平原 240 秒剩 1：4 仍在纏鬥；丘陵 140 秒敵軍（高地方）勝；森林 60 秒敵軍勝；**河谷**敵軍涉水強攻，我軍守岸 49：27 大勝；雪地 80 秒敵軍勝。
  場地確實會改變戰局，但兵種與地形的平衡都還沒調。
- 雲端邏輯成本（400 人、MultiMesh、不死亡）：丘陵 6.9 ms、森林 6.7 ms、河谷 7.3 ms／物理步（同時在錄影，數字偏高；之前平地約 5 ms）。

### 攻城戰（`scripts/siege/siege_map.gd`＋`battle_manager.gd` 的攻城段落）
按 **F10** 從野戰切到攻城戰（再按一次回野戰），先跳出選邊畫面：**攻城方 400 人**或**守城方 200 人**。遊戲中按 **F11** 換邊並重開。也可用啟動參數 `--siege=attack` 或 `--siege=defend` 直接進入。

- **場地**：一道南北向、貫穿整張地圖的城牆（高 6.5 公尺、牆頂走道 4 公尺寬、外側有城垛）。中央是城門（兩側有外凸塔樓），城內有兩條登城坡道和一座主堡。全部是佔位方塊。
- **雲梯**：照你說的做法，開局就有 3 道雲梯架在牆上（不用架設）。士兵一個接一個爬（同一道梯子間距約 0.9 公尺、約 3.4 秒爬上去），梯頂有敵人擋著就上不去，只能在梯頂跟他打。被打死的人從梯子掉下去。玩家也可以走雲梯上牆（雲梯是一塊 62° 的斜板）。
- **攻城槌**：2 隊推槌兵推著槌從西邊往城門走，槌旁人越多走越快（至少 2 人才推得動），到了城門每 2.4 秒撞一次。城門 1500 血、每次撞 125。城門破了以後門洞可以通行，攻方騎兵和推槌兵改成衝進城，守方的城門守衛和預備隊也出來堵門。
- **攻城 AI**：開局 6 秒後步兵開始進攻，每隊分配一道雲梯（8 隊一道梯）。弓兵在城外約 30 公尺排成一線壓制牆頂。騎兵等城門破了才出動。攻上牆的人會從坡道下到城內繼續打。近戰兵都死光了，弓兵也會拔刀爬梯。
- **守城 AI**：弓兵站在牆頂（有高地加成），每道梯頂兩側各守一隊步兵，城門後面兩隊，其餘是城內預備隊。哪道梯子有 3 個以上攻方爬上牆，就從預備隊派一隊上去增援。守方近戰兵不會爬梯子出城追人（城門破了只守門口），等攻方剩不到守方三成時才出城追擊。
- **勝負**：一方全滅，或 10 分鐘到了攻方還沒打下來就算守方勝。
- **編成與平衡（第二版）**：兩方兵的素質一樣，守方靠城牆守住。
  - 攻方 400：長槍步兵 280（其中 20 人推攻城槌）、弓兵 80、騎兵 40。
  - 守方 200：劍盾兵 130、弓兵 70。劍盾兵（只有守方有）出手比長槍快，正面的盾有 4 成機率擋下近戰，正面中箭傷害減半。畫面上暫時用劍＋盾的步兵圖。
  - 牆頂弓兵會探出城垛往下射，射得到牆腳和梯子上的人；牆頂守軍有城垛掩護，箭傷 ×0.5。
  - 雲梯難爬：爬梯的人出手傷害 ×0.8，梯頂 1.3 公尺內有守軍就上不去。高低差的傷害加成只有弓箭有，近戰沒有。
  - 城門 3200 血（約 2 分半撞破）。破門後守方的城門守衛和預備隊在門洞後面列陣堵門，不出城。
  - 雲端 AI 對 AI（玩家不動）：守方兩場都贏：攻方視角約 5 分鐘守方剩 48 人，守方視角打到 10 分鐘才分出勝負，守方剩 13 人。破門後雙方都損失很大，戰局接近。數值在 `battle_manager.gd` 的 `SWORD_*`、`LADDER_*`、`SIEGE_WALL_ARROW_MULT`，以及 `siege_map.gd` 的 `GATE_HP`、`RAM_*`。
- **箭會被城牆擋住**：女兒牆、城垛、塔樓、城門都會擋箭，所以牆頂守軍有一部分掩護。
- 士兵的「層」：士兵仍然不進物理引擎，只多記一個所在層（地面／牆頂與坡道／雲梯上）。不同層的人不會互相推擠或砍到（高度差超過約 1.7 公尺）。跨層移動走導航點（梯腳 → 梯頂、坡道底 → 牆頂、城門），由 `SiegeMap.waypoint()` 決定。
- 1／2／3 命令在攻城戰也能用：2「在此集結」如果你站在牆頂，隊伍會沿著走道排開。
- 已知限制：鏡頭不會避開城牆，所以在牆邊轉鏡頭可能看進牆裡。玩家沒有摔落傷害。馬上不了牆和雲梯。

## 4. 壓力測試（階段 3，決策點）

### 在編輯器裡執行（最簡單）
1. 在檔案系統面板打開 `scenes/stress_test.tscn`。
2. 按 **F6**（執行目前場景）。
3. 會自動依序測：**Sprite3D 50／100／200 人 → MultiMesh 50／100／200 人**，每次暖機 3 秒＋記錄 20 秒，總共約 2.5 分鐘。期間相機會自動繞場，不用操作。
4. 測完畫面會顯示摘要表，**摘要同時已複製到剪貼簿**，直接貼回對話給我即可。按 Esc 結束。

### 用命令列執行（可自訂參數）
```bash
# Windows 範例（路徑換成你的 Godot 執行檔）
"C:\Godot\Godot_v4.5.1-stable_win64.exe" --path . res://scenes/stress_test.tscn -- --counts=50,100,200,400 --quit

# macOS 範例
/Applications/Godot.app/Contents/MacOS/Godot --path . res://scenes/stress_test.tscn -- --counts=50,100,200
```
`--` 之後的參數：

| 參數 | 說明 |
|---|---|
| `--counts=50,100,200` | 士兵總數（雙方合計），可加 400、800 找上限 |
| `--backends=sprite,multimesh` | 要測的士兵畫面後端 |
| `--duration=20` `--warmup=3` | 每次記錄秒數與暖機秒數 |
| `--immortal` | 士兵不死亡，整段維持固定人數 |
| `--no-postfx` | 關閉景深／泛光／SSAO／霧，比較後製成本 |
| `--quit` | 測完自動關閉 |

### 結果檔案位置
- Windows：`%APPDATA%\Godot\app_userdata\HD-2D Battle Prototype\stress_results\`
- macOS：`~/Library/Application Support/Godot/app_userdata/HD-2D Battle Prototype/stress_results/`
- Linux：`~/.local/share/godot/app_userdata/HD-2D Battle Prototype/stress_results/`

每次測試會產生：`stress_時間.txt`（摘要表，含 CPU／GPU 型號）、`stress_時間_summary.csv`、每一輪的逐幀 CSV。

### 摘要表欄位
| 欄位 | 意義 |
|---|---|
| 平均 FPS／1% 低 FPS | 1% 低 = 最慢 1% 幀的平均，代表卡頓感 |
| 平均幀 ms／P99／最差幀 ms | 幀時間分布 |
| 邏輯平均／最差 ms（網格／決策／移動） | 戰場管理器每個物理步（60Hz）的耗時與分解 |
| 畫面更新 ms | 視覺代理把士兵資料寫進 Sprite3D／MultiMesh 的耗時 |
| CPU 繪製 ms／GPU ms | 引擎渲染耗時（GPU 量測依驅動支援） |
| DrawCalls | 每幀繪製呼叫數，MultiMesh 應明顯較少 |
| 結束存活 | 測試結束時雙方存活人數 |

**目前不設幀率門檻**，看完數據再決定：繼續 → 階段 4，或先把熱點改寫（C#／GDExtension）、改用 MultiMesh、降低同場人數加增援波次。

### 雲端參考數據（只有邏輯，沒有繪圖）
雲端環境沒有顯示卡，以下只代表「戰場邏輯」在 4 執行緒 2.1GHz Xeon 上的耗時，**畫面相關數字要以你電腦的結果為準**：

三兵種版本（含弓兵箭矢、騎兵衝撞）：

| 士兵數 | 邏輯平均 ms／物理步 | 最差 ms | 移動與戰鬥 | 決策 |
|---|---|---|---|---|
| 50 | 0.57 | 2.9 | 0.43 | 0.06 |
| 100 | 0.98 | 5.9 | 0.75 | 0.14 |
| 200 | 2.2 | 8.9 | 1.6 | 0.40 |
| 400 | 5.1 | 13.7 | 3.5 | 1.3 |

以 60Hz 物理步、一幀 16.7 ms 來看，200 人時邏輯約占 13%；400 人時約占 30%。平均耗時和只有步兵時差不多，但最差尖峰變高、決策成本隨人數增加較快（弓兵射程大，找敵改成線性掃描）。熱點仍在「移動與戰鬥」（分離力的鄰居迴圈），是之後改 C#／GDExtension 或降頻的首選目標。

## 5. 架構概覽

```
scripts/
  core/game_config.gd          全域暫定選項（方向數、士兵畫面後端、Billboard、後製、亂數種子）與輸入對應
  world/battle_terrain.gd      高度圖地形：網格＋HeightMapShape3D（給玩家/馬）＋ get_height()（給士兵）
  camera/orbit_follow_camera.gd 可旋轉第三人稱追隨相機（移軸景深）
  actors/horse.gd              馬：CharacterBody3D＋自訂加速、轉向率、慣性
  actors/player.gd             玩家：步行/騎乘、上下馬、掃掠揮擊、傷害公式
  battle/battle_manager.gd     集中式戰場管理器：士兵資料陣列、空間網格、三層 AI、戰鬥、命令佇列
  battle/soldier_renderer.gd   士兵視覺代理介面（共用：方向、動作幀、陰影）
  battle/sprite_soldier_renderer.gd     實作 A：每人一個 Sprite3D
  battle/multimesh_soldier_renderer.gd  實作 B：全體一個 MultiMesh（shaders/soldier_billboard.gdshader）
  visual/direction_util.gd     朝向 → 方向圖欄位（8 欄規格；4 方向、5＋鏡像由設定決定）
  visual/anchor_set.gd         錨點資料（之後可由 Aseprite 匯出的 JSON 轉入）
  visual/layered_actor_visual.gd 主圖層＋附掛圖層（馬＋騎士）＋陰影的視覺代理
  visual/placeholder_art.gd    程式產生的佔位像素圖與錨點
  debug/stress_test.gd         壓力測試
  debug/scenario_runner.gd     開發用自動腳本（模擬按鍵＋截圖）
```

設計原則（依研究報告）：
- **戰鬥邏輯與畫面分離**：位置、命中都在 3D 空間用數學計算；Sprite 只負責「看起來像」。士兵畫面換成 MultiMesh 或預渲染 3D，戰鬥程式不用改。
- **士兵不進物理引擎**：只有玩家和馬是 CharacterBody3D。士兵靠高度圖貼地、靠空間網格互相分離與找敵。
- **方向數是設定值**：素材一律按 8 欄排；4 方向或 5＋鏡像只是換算方式不同。
- **分層＋錨點**：騎士的座位錨點對齊馬當前幀的鞍座錨點，奔馳起伏時騎士會跟著動；面向鏡頭時馬頭畫在騎士前面。
- **固定步長與固定種子**：戰鬥在 60Hz 物理步結算；同一種子重跑結果一致（雲端實測兩次 50 對 50 結果相同）。
- **命令只寫入佇列**：玩家下令不直接改士兵狀態，由小隊層下一次決策時取用。

## 6. 已知限制與下一步

- 士兵沒有士氣／撤退、沒有尋路（開闊地直走＋分離力；岩石用圓形障礙推開）。
- 個人 AI 的「遠處每 2～4 幀移動一次並內插」尚未實作，目前所有士兵每個物理步都移動；這是壓力測試後最直接的優化點。
- 長槍「卡住」目前是距離判定（目標比 1.1 m 近就算），還沒有真的檢查槍桿有沒有被其他人或障礙物擋住；舉盾只看方向（正前方 75° 內），近戰和箭都擋得下，沒有耐久或體力消耗。
- 敵方指揮官只是「10 秒後或被逼近時全軍衝鋒」的佔位 AI；完整命令與分層 AI 屬於階段 6。
- 相機不會自動轉到馬的背後，需要用滑鼠轉；騎馬手感與相機行為等你試玩後再調。
