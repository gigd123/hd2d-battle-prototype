# 美術流程：3D 預渲染成像素圖

這份文件說明怎麼用 `tools/sprite_baker` 把 **低模 3D 角色** 自動烘焙成遊戲用的 **8 方向分層像素圖**。
目標是讓美術量降到「做一次 3D 模型＋套動作，剩下交給程式」，你只需要修少數關鍵幀。

原型已經內建一組程式生成的騎士與馬（原創、全部用方塊與圓柱組成），
`art/baked/` 裡的圖就是用它烘出來的。遊戲裡按 **F7** 可以切換「預渲染圖 ↔ 舊佔位圖」比較。

---

## 1. 流程總覽

```
概念圖（AI 出圖或手繪）
   ↓
低模 3D 模型（AI 圖轉 3D、或 Blender 自己拉方塊）
   ↓
自動綁骨＋套動作（Mixamo 等）→ 匯出 .glb
   ↓
寫一份 JSON 設定（圖層、動作、錨點）
   ↓
執行烘焙器 → 每個圖層一張 8 方向圖集 + sprites.json
   ↓
（可選）在 Aseprite 修關鍵幀
   ↓
遊戲直接讀取（玩家、馬、騎士、三兵種都已接好）
```

## 2. 先跑一次內建範例

需要一般版 Godot 4.5 以上（有顯示卡即可，不需要 .NET 版）。

**在編輯器裡：** 開啟 `tools/sprite_baker/bake_sprites.tscn`，按 **F6**（執行目前場景）。
視窗會閃一下並自動關閉，輸出在 `art/baked/horse/` 與 `art/baked/knight/`。

**用命令列：**

```bash
# 烘焙預設的兩份設定（馬、騎士）
godot --path . res://tools/sprite_baker/bake_sprites.tscn

# 只烘焙某一份
godot --path . res://tools/sprite_baker/bake_sprites.tscn -- --config=res://tools/sprite_baker/configs/knight.json

# 把內建模型匯出成 glb（可以在 Blender 打開，當作自己做模型的範本）
godot --path . res://tools/sprite_baker/bake_sprites.tscn -- --export-glb=res://art_src
```

> 不能加 `--headless`：烘焙需要真的渲染畫面。雲端測試時騎士＋馬全部（約 2,400 次渲染）大約 40 秒。

烘完先看 `art/baked/<名稱>/preview.png`（所有圖層疊好、套上藍色陣營色的總覽），再進遊戲按 F5 執行。

## 3. 輸出的檔案

| 檔案 | 內容 |
|---|---|
| `<圖層>.png` | 圖集：**8 欄 = 方向**（S、SE、E、NE、N、NW、W、SW；S = 面向鏡頭），**每列 = 一個動作幀** |
| `<圖層>_team.png` | 陣營色遮罩：白色像素在遊戲裡會乘上陣營色（保留原本的明暗），只有含 Team 零件的圖層才有 |
| `sprites.json` | 幀大小、每像素公尺數、原點、動作表（起始列、幀數、fps、是否循環）、每一格的錨點座標 |
| `preview.png` | 檢查用總覽，遊戲不讀 |

內建騎士有三個圖層：`body`（身體＋盾）、`sword`、`spear`。
**同一套動作、換武器只要換武器層**，身體不用重畫；遊戲裡玩家用劍、步兵用長槍就是這樣做的。

## 4. 換成你自己的模型

### 4.1 準備模型

- **來源**：
  - AI 圖轉 3D 工具（上傳一張概念圖產生 3D 模型）。請確認該工具的**商用授權條款**。
  - 或在 Blender 用方塊、圓柱自己拉低模。像素圖最後只有 40 像素高，**細節越少越好**，大色塊比精緻貼圖更好看。
- **面向 +Z**（glTF 的標準方向，Mixamo 匯出的就是）。如果你的模型面向 -Z，設定裡寫 `"forward": "-Z"`。
- **原點在腳底，1 單位 = 1 公尺**（人大約 1.8 高）。單位不對可以用 `"scale"` 調整。
- **武器做成獨立物件**，名稱用固定開頭，例如 `Sword_Blade`、`Spear_Shaft`。
- **陣營色的零件**（外衣、盾面、鞍布）名稱裡加 `Team`，例如 `Tunic_Team`，顏色用淺灰。
- 材質只要基本色（或一張基本色貼圖）就好，烘焙器會自動換成分階明暗。

### 4.2 綁骨與動作

- 人形角色可以用 **Mixamo**（免費，需要 Adobe 帳號；上傳模型 → 自動綁骨 → 挑動作 → 下載）。下載時選「In Place」（原地動作）。授權請以 Mixamo 官方條款為準。
- 也可以在 Blender 用 Rigify 或手動擺關鍵姿勢。騎乘姿勢 Mixamo 沒有現成的，坐姿動作改一改即可。
- 所有動作放在同一個 glb 裡（Blender 的 NLA／Action 都會匯出成動畫），動畫名稱要和設定裡的 `anim` 一致。
- 馬這類四足動物目前沒有好用的免費自動綁骨，建議用 Blender 手動綁，或沿用內建馬改造型。

### 4.3 錨點

錨點是「這一格的某個點在圖上哪裡」，例如騎士的 `seat`（屁股）要貼到馬的 `saddle`（鞍）上。
在模型裡放一個**空物件**（Empty）並取名，例如 `Seat`、`Saddle`、`WeaponTip`；
或直接寫**骨頭名稱**（例如 Mixamo 的 `mixamorig:Hips`），烘焙器會自動掛上去。

### 4.4 寫設定檔

複製 `tools/sprite_baker/configs/knight_glb_example.json`（讀 glb 的範例）修改即可。重點欄位：

| 欄位 | 說明 |
|---|---|
| `name` | 圖集名稱，遊戲用這個名字找（`art/baked/<name>/`） |
| `output` | 輸出資料夾，預設 `res://art/baked/<name>` |
| `source` | `builtin:knight`／`builtin:horse`，或 `.glb`、`.gltf`、`.tscn` 路徑 |
| `frame_size` | 每格像素大小。要能裝下揮劍的範圍，太大只是浪費 |
| `pixel_size` | 每像素幾公尺。0.045 ≈ 人 40 像素高；改成 0.06 會更粗獷（≈ 30 像素） |
| `pitch_deg` | 俯角（度）。30 左右看得到頭頂與馬鞍；越小越像側視 |
| `bottom_margin` | 腳下留幾像素（斜看時前腳、倒地的身體會低於原點） |
| `supersample` | 超取樣倍數，4 = 先畫 4 倍大再縮小，邊緣較乾淨 |
| `color_levels` | 顏色量化級數（每個顏色通道）。越小顏色越少、越好修；0 = 不量化 |
| `outline` / `outline_darken` | 是否加 1 像素外框、外框比相鄰顏色暗多少 |
| `shade_mid` / `shade_dark` / `light_dir_view` | 分階明暗的亮度與光線方向（鏡頭座標） |
| `layers` | 圖層清單，**由下往上**。`include`／`exclude` 用物件名稱比對（可用 `*` 萬用字元），`team` 標陣營色零件 |
| `anchors` | `錨點名: 物件或骨頭名稱` |
| `actions` | 動作清單：`name`、`anim`（動畫名，省略 = 同 name）、`frames`、`fps`、`loop`，可選 `start`／`end`（秒）只取一段 |
| `holdouts` | 遮擋物：例如騎乘動作時放一匹看不見的馬，騎士被馬擋住的地方（另一側的腿）會自動挖空 |

圖層的遮擋規則：**較上層的圖只保留「在下層前面」的像素**。所以疊圖時順序固定、不用每格判斷前後；
換一把不同形狀的武器只要重烘武器層，身體層不受影響。

### 4.5 讓遊戲用新圖

遊戲目前讀 `knight` 與 `horse` 兩組。最簡單的做法：新設定的 `name` 也取 `knight`（或 `horse`），烘完直接取代。
要新增兵種時，在 `scripts/battle/soldier_art.gd` 加一組對應即可。
動作名稱需要包含：騎士 `idle`、`walk`、`run`、`attack_a`、`attack_b`、`death`、`ride_idle`、`ride_attack_a`、`ride_attack_b`；馬 `idle`、`trot`、`gallop`。

## 5. 修圖

烘出來的圖已經是乾淨的像素圖（量化過的顏色、1 像素外框），大部分格子可以直接用。建議：

1. **只修定稿**：模型、動作、參數都滿意了再修，不然重烘會蓋掉修過的圖。
   修之前先 `git commit` 一次，或把 `output` 改到另一個資料夾，修好再複製進 `art/baked/`。
2. **工具**：Aseprite（付費，像素圖最順手）、LibreSprite（免費）、Krita／Photoshop（關掉反鋸齒、用鉛筆工具）。
   在 Aseprite 可以用「Import Sprite Sheet」按 88×88 切格，修完「Export Sprite Sheet」原樣輸出。
3. **不要改圖集尺寸與格子位置**，錨點資料是按格子算的。
4. **優先修的地方**（投資報酬率最高）：
   - 玩家最常看到的方向（S、SE、SW）和待機、走路
   - 臉／頭盔的辨識度（低模縮小後常糊掉，手點 1～2 個高光就差很多）
   - 細長物（劍、槍）斷掉的像素、零星的單顆雜點
   - 揮擊的最快那一格可以手加一道拖影
5. **陣營色**：修 `body.png` 時，如果改到外衣的形狀，`body_team.png` 也要跟著改（白 = 要換色）。

## 6. 已知限制（原型階段）

- 騎士另一側的腿是用「站著的馬」當遮擋物挖空，奔馳時馬身上下起伏，邊緣偶爾差 1 像素。
- 弓兵還沒有弓的模型，暫時拿劍。
- 內建模型與動作是程式寫的，動作只求能看懂（揮擊、騎乘偏僵硬）；換成 Mixamo 動作會自然很多。
- 預渲染圖本質上還是「3D 縮小」的質感，想要更有手繪味，就靠第 5 節修關鍵幀，或把 `color_levels` 降到 8～12。
